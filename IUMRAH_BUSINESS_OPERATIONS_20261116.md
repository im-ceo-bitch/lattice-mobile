# iumrah Business — Operations / Security Blue (2026-11-16)

Накопительный overlay для `lattice-mobile-main 5.zip`. Файлы расположены относительно корня репозитория. Не содержит секретов, сборок, новых workflow или замен клиентского репозитория.

## Изменения
- Общая чёрная навигационная поверхность, синяя палитра Orbit V5 без изменения геометрии; обзор, бронирования, чаты и каталоги. Непрочитанные чаты, поиск брони, переходы из push по идентификатору. Каталоги сохранены.
- Конфигуратор: пять рабочих этапов (перелёт/параметры, отели, услуги, итог, клиент). Сохранён защищённый черновик. Источники рейсов разделены по метаданным существующего опубликованного каталога. Aviasales не вызывает Data API; при отсутствии записей — ручной ввод. Внешняя проверка расписания только по отдельной кнопке. Стоимость билета туда-обратно учитывается один раз, если однозначно известен тариф; иначе ручная сумма. Кэш номера отеля применяется только при совпадении условий и свежести, не является подтверждением наличия. Питание и услуги менеджер проверяет самостоятельно.
- Новый защищённый POST `/api/admin/bookings`: действующая staff cookie + активная бизнес-сессия устройства; серверный пересчёт USD, приватная себестоимость, идемпотентное создание записи и история. Существующая клиентская проверка подписанной цены не ослаблена. D1-таблица `business_manual_bookings` создаётся аддитивно при запросе. Бронь создаётся в статусе проверки наличия, а не покупки инвентаря. Номер и iumrah ID возвращаются при успешной материализации идентификаторов; иначе можно повторить проверку.
- Закрытая ссылка просмотра с отдельным токеном (не booking access token); токен во фрагменте URL, данные только на чтение, без паспортов/телефонов/себестоимости. Менеджер может перевыпустить ссылку, предыдущая перестаёт действовать. Ссылка открывает русскоязычную страницу на текущем Worker; это не Universal Links и не полноценный клиентский интерфейс. Сумма предварительная.
- Email через существующий Resend (если ключ и отправитель настроены), четыре языка письма, результат принятия провайдером; SMS/WhatsApp — вручную через системный Share, без новых платных интеграций. Автоматический SMS не подключён. Отдельный режим предложения без брони не реализован (есть черновик и реальная заявка).
- Диагностика APNs: разрешение, токен, конфигурация сервера, тест текущего устройства. Никакого Firebase. Успешный ответ APNs не доказывает доставку на устройство. Поддержка deep link на конкретную бронь/чат при наличии ID в уведомлении.

## Установка
1. Убедиться, что `main` соответствует базе `lattice-mobile-main 5.zip`; сохранить резервную копию/коммит. Загрузить `iumrah-business-operations-20261116.zip` **в корень**, без ручного изменения workflow. Дождаться успешного `Apply iumrah Business ZIP update` (он распаковывает архив, удаляет его и коммитит файлы).
2. Вручную запустить `Deploy iumrah backend` на main. Сначала backend, затем приложение. Не создавать новые D1/R2 и не менять секреты без необходимости.
3. Вручную запустить `iumrah Root — iOS TestFlight (new Team)` на main. Проверить compile-only preflight и сборку. На iPhone проверить экран блокировки, навигацию, ручную тестовую заявку, письмо, ссылку, изменение статуса, тест push; проверить также iPad/Mac Catalyst.
4. Для отката — revert коммита распаковщика и повторный деплой; уже созданные бронирования и таблицы остаются в БД, не удалять их автоматически.
