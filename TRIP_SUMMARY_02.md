# iumrah Trip Summary 2.0 — cumulative stage 02

This patch includes all stage 01A changes plus stage 02. Apply to the original supplied repositories. No previous update is required. The archives are repo-root patches, not full repository copies. Deploy Business/backend first using the existing Deploy iumrah backend workflow, then build the iOS clients.

## Stage 02 scope
- The existing shared FinalPackageView now renders the new compact Trip Summary UI. Manual, Smart, and the main flight-first flow keep the existing verified booking confirmation. Compatibility LocalJourneyReviewView points to the same surface.
- Summary, dates and stay counts; editable flight, hotel/room and transfer selection; private services, visa and support; expandable prices, monochrome chart, planned calendar, booking/refund terms, final total and actions. UI uses existing assets and design system. New copy uses RU, EN, UZ, UZ-Cyrl via existing localization helper (other locales follow its fallback).
- Guest draft with separate adults, teens, children and infants; exact ages required before applying a changed party. Only adults trigger the special >5 per room warning; the sixth adult adds a second room automatically. Supplier occupancy is still separately checked. The normal bookable allocation is preserved until a manager exception is implemented. Known catalogue room capacity and single-vehicle capacity are checked; large families that exceed available vehicle capacity need manual arrangement. Current provider limit is 9 total travelers. Hotel rates are reselected after occupancy changes. Prices are recalculated from the server, not recomputed on the phone. Pending edits and unaccepted new prices prevent booking.
- Hotel rate cancellation rules are displayed where returned by the supplier; other flight/hotel cards show the default caveat. Transfer policy is 24 hours and up to $100 late fee before service, remaining amount returned; services refundable before start; visa refund before submission and non-refundable afterwards. Actual refunds and issuance are not executed in this stage.
- The quote response can include a planned itinerary from the existing server booking planner, only when the verified schedule and authoritative stay dates agree. If the planner and supplier stay disagree, the app displays known dates/flights without invented activity times. Check-in/out times are planned, not guaranteed supplier confirmations.
- Save action uses the authenticated saved-package API from stage 01A; guest capability is stored in Keychain; the same screen can update the package revision. Save-and-share generates a local PNG and uses native sharing. The public read-only link/OG, cross-session saved-package list/recovery, actual package-linked chat/manager exception workflow and booking conversion are not completed here. Support shows save gate and a localized shareable draft, not a fake chat transmission.
- The card states visas first, then ticket purchase after approval. Automatic execution, operational status UI, actual refund screen/processing, public sharing and chat are stage 03 work. The independent legacy storefront offer checkout was not migrated in this patch. Guide/ziyarat information is shown, not an unimplemented service picker.
