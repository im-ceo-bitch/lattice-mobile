# iumrah Business V34 — Performance & Cache

База: полный архив `lattice-mobile-main 3.zip` + применённые V32 и V33. Последний подтверждённый деплой №34 успешен. Патч предназначен для репозитория, в котором V33 уже установлена.

## Изменения

- Память: изолированные по текущему токену сеанса ограниченные кэши. История чатов — до 12 диалогов, до 8 МиБ сериализованных данных, 5 минут; изображения чата — до 40 объектов, до 24 МиБ данных, 2 минуты; каталог отелей — до 4 МиБ сериализованных данных, 1 минута. Это бюджеты полезных данных, не гарантированный предел RSS процесса. История с более чем 2000 сообщениями не сохраняется в новом снимке кэша, но остаётся доступна на сервере. При смене сеанса, выходе, определённых ошибках авторизации и предупреждении о нехватке памяти кэш очищается.
- Чат: повторный вход использует сохранённый курсор и серверную проверку области доступа, а затем загружает дельту. Кэш истории не отображается до успешной проверки. При смене области история сбрасывается. Одновременные запросы обновления объединяются с повторным проходом, если во время загрузки пришло новое событие. Резервный опрос — 15 секунд, при ошибке — 30 секунд; фоновый опрос приостановлен. Курсор прочтения остаётся привязан к полученным сообщениям. При перезапуске приложения память пуста.
- Изображения чата: запрос через авторизованный APIClient на доверенный маршрут вложений вместо AsyncImage. Сетевой HTTP-кэш APIClient отключён. Паспорта, чеки и произвольные ссылки не входят в новый кэш. Никаких новых файлов с клиентскими данными на диске не создаётся.
- Отели: быстрый предварительный показ последнего каталога с явной маркировкой и блокировкой действий по устаревшему снимку; всегда выполняется свежий запрос. Каталог, health и импорты запускаются параллельно. Опрос импортов выполняется только в активной сцене, через 3 секунды при активных импортах или через 20 секунд без них. Защита от запоздавших ответов при изменении импортов.
- Primary Hotels: при смене города не перечитывается весь каталог, если он уже загружен; назначения читаются заново. Правки доступны только после успешной загрузки выбранного города. Pull-to-refresh перечитывает каталог и назначения.
- Overview: сохраняет последние доступные данные при частичном сбое, показывает предупреждение, не заменяет результат на фиктивный пустой список; защита от запоздавших ответов.

## Проверки

- Основной серверный набор: 116 Unified Backend + 39 Flight Hub + 100 Package Engine + 20 Core Migration = 275/275. Серверный код не изменён.
- Расширенный HotelsWorker: 152/185, ровно те же 33 падающих теста, что на исходной V33 (сравнение списка имён).
- 17 проверок реального Swift-кэша: изоляция, TTL, LRU, лимиты, смена токена, очистка.
- 19 проверок фактических методов синхронизации Swift-чата с имитацией API: восстановление курсора, дедупликация, смена области, отказ сервера, входящие события, отмена сеанса.
- Все 73 Swift-файла Sources прошли парсер. APIClient и изменённые методы загрузки Overview/Hotels/Primary Hotels прошли проверку типов Swift с платформенными заглушками. Architecture: 3/3. Umrah draft behavioral checks: PASS.
- Не проверены: полноценная компиляция SwiftUI/Xcode, реальные APNs, отрисовка на iPhone/iPad/Mac, фактические метрики производительности. Локальные проверки не заменяют финальный TestFlight.

## Запуск тестов кэша

Из корня репозитория с установленным Swift:

```bash
swiftc -swift-version 5 Sources/Networking/BusinessSessionMemoryCache.swift Tests/Performance/BusinessSessionMemoryCacheTests.swift -o /tmp/iumrah-business-cache-tests
/tmp/iumrah-business-cache-tests
python3 Tests/Performance/run_chat_cache_tests.py
```

## Установка

Загрузить ZIP в корень Business-репозитория, дождаться распаковки существующим workflow. V34 не требует деплоя Cloudflare; TestFlight отложен до окончания V35/V36 по решению владельца. Нет изменений в `.github/workflows`, D1/R2, iOS-клиенте и секретах. Архив не предназначен для установки на чистый старый репозиторий без V33.
