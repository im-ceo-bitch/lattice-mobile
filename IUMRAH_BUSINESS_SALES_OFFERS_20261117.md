# iumrah Business — Sales & Offers · 2026-11-17

Накопительный overlay поверх `lattice-mobile-main 5.zip` + `iumrah-business-operations-20261116.zip`. Не содержит `.github/workflows/`, не меняет расписание/код авиаботов. Существующий Apply ZIP workflow распаковывает в корень.

## Что включено

- Единый конфигуратор, два действия: предложение без контактов или бронирование с контактом. Старые незавершённые ручные бронирования продолжают использовать прежний API.
- Package ID (PKG-UUID), одна защищённая ссылка на Worker: `/api/offers#<64 hex>`. Сохраняется после конвертации, кроме явного отзыва/ротации менеджером. Токен хранится в staff-only строке D1 для возможности повторно поделиться; публичный запрос ищет по SHA-256, fragment не передаётся в URL HTTP-запроса. Ссылка — bearer capability; не пересылать посторонним. Не выдаёт телефон, имя, ID паломника, документы, access token бронирования или себестоимость.
- `business_offers`, `business_offer_events` создаются идемпотентно в существующей BOOKINGS_DB при первом обращении. Не нужны новые binding или секреты. Версии пакета и сроки 24/48/168 ч (не позже вылета), редактор, отзыв, ручная отметка отправки, события, счётчик открытий ссылки. Предпросмотр `?preview=1` не считает просмотры и не позволяет забронировать через интерфейс.
- API `GET/POST /api/admin/offers`, `GET/PATCH /api/admin/offers/:id`, `POST /api/admin/offers/:id/accept`; публичные `GET/POST /api/offers`, `POST /api/offers/accept`. Все административные операции требуют staff cookie + активный Business device session. Сумма рассчитывается сервером по сохранённой себестоимости и комиссии. Конвертация в существующие bookings/booking_events/business_manual_bookings — атомарная D1 batch с проверкой state/revision/expiry, без дубликатов. Клиентский quote-proof flow не ослаблен.
- При создании активного бронирования вызывается существующая materializeBookingIdentity (номер брони и iumrah ID); если операция не готова, менеджер может повторить. При наличии RESEND_API_KEY запрошенный email отправляется через существующий Resend; статус принятия провайдером не равен фактической доставке. Клиентский email необязателен. У менеджера доступно системное ShareLink; SMS/WhatsApp/Telegram автоматически не отправляются.
- Push через существующую APNs реализацию на первый учтённый просмотр и создание бронирования. Открытие первого push ведёт к предложению, второго — к бронированию. События не дублируются при повторных запросах. Фактическая доставка зависит от конфигурации APNs; автоматического напоминания об истечении срока нет. Ошибка push не отменяет бронирование, отдельной очереди повторной доставки offer-push пока нет.
- Business: вкладка бронирований с сегментом предложений, поиск, фильтры, статистика по последним 250 предложениям (прямые бронирования исключены), детали и история. Счётчик — открытия ссылки, не уникальные люди, а ручная отметка отправки не является подтверждением доставки.
- Worker содержит самостоятельную мобильную веб-страницу RU/UZ/UZ-Cyr/EN с пакетом и формой бронирования без регистрации. Статус после конвертации читается из существующего booking/операционного состояния. Операционные изменения маршрута и документов через клиентский портал не реализованы: страница отображает сохранённый состав и текущий статус, а не полный личный кабинет. Отдельные клиентские iOS/Android и основной Next.js сайт не изменены; Universal Links и собственный домен для этой ссылки — следующий этап.

## Деплой

1. Загрузить `iumrah-business-sales-offers-20261117.zip` в корень Business GitHub repo.
2. Убедиться, что Apply iumrah Business ZIP update завершился.
3. Запустить вручную Deploy iumrah backend. Core должен быть уже активирован и иметь BOOKINGS_DB, HOTELS_DB.
4. Собрать iOS TestFlight существующим workflow. Не запускать airline monitors.
5. В TestFlight создать предложение на будущие даты. Предпросмотр не увеличивает счётчик; открыть обычную ссылку с другого устройства, принять предложение, проверить номер, статус, появление в Business, повторное принятие. Проверить APNs и email отдельно, а также ротацию ссылки. Не тестировать реальным бронированием поставщика.
