Cumulative root-overlay patch. Includes Sales Offers, Business UI Final, Foundation 1A/1B, Stage 2A and Stage 2B. If Stage 2A and 2B were not applied, this ZIP replaces both. ## Stage 3
- Business queue of operational tasks: availability (actual 30-minute expectation), payment/receipt, documents (deadline), departures, in-trip, cancellation requests, refunds and assignment. Priority ordering, task filters, assigned-to-me view; preserve status/search and offer views. Assign active owner/manager/operations team member. Push cancellation requests to staff, refresh list after operations. Existing status IDs preserved.
- Business workspace Overview/Trip/Documents/Finance: stage-specific primary action, independent service checklist derived from included package components, supplier references, availability and execution states, notes; separate passports/document center from payment/review/pricing. Manual transitions remain subject to server gates. Flights and hotels tracked separately; group service items (e.g. transfers) use one service-level entry. Changed flight/assignment/scope invalidates confirmation; staff must reconfirm old packages before next gated transition. Explicit active guide assignment required when included. All required services confirmed before availability and readiness; published documents still mandatory. Service execution requires explicit staff action before completion.
- Itinerary execution states independent of clock; edited schedule events reset previous execution; client consumes manager-authored schedule and localized execution states. Existing generated itinerary fallback retained when no managed itinerary. In-trip support via service operations; full companion UX belongs to Stage 4.
- Cancellation: client requests using verified booking token; status stays active pending manager decision. Staff can close request with reason or cancel with reason and reviewed receipts. Booking, receipts, files, history retained. Legacy destructive booking routes rejected. Refund ledger records actual external transfers only, requires positive amount and external reference, duplicate reference and amounts above verified payment rejected. Outstanding is unallocated confirmed funds, not a decision about the contractual refund amount. No money sent automatically. Historical unverified payments must be reconciled before full settlement; policy fees/partial retention not implemented as financial closing in this stage.
- Additive repeatable schema in existing workflow-applied 0044 migration. Per-booking mutation lease for status, receipts, service/assignment of responsible manager, cancellation, refund, and itinerary execution actions. Source/operational status synchronization uses two D1 databases; lease is not a distributed atomic transaction. No existing data dropped; operational history recorded.
