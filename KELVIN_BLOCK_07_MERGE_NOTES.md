# Kelvin — Block 07: Production Readiness / локальная инженерная проверка

## Статус и границы
Работа проведена на восстановленной версии из предыдущих архивов, а не на актуальном GitHub HEAD. Текущий новый интерфейс iumrah Business ещё не предоставлен. Исходная версия интерфейса проверялась только как прежний референс; не включена в новый backend-only ZIP. Никаких изменений production, реальных клиентских данных или настроек Mac не выполнялось. Статус: кандидат на интеграционную приёмку, НЕ подтверждённый production release.

## Изменения блока 07
- `founder_jarvis/operations.py`: ежедневный локальный снимок jobs.sqlite3, autonomy.sqlite3, advisor-scheduler.sqlite3 и voice-language.json; online SQLite backup с WAL, проверка quick_check, SHA-256 манифест, временная директория и атомарное переименование, хранение семи снимков. Восстановление только в новую директорию для офлайн-инспекции. Секреты runtime.env и iumrah-link.json не включены. Снимки отдельных БД не являются единой атомарной транзакцией. Не восстанавливать старые очереди в live runtime без сверки доставок и D1. Каноническая D1 требует отдельного backup средствами Cloudflare. Локальный журнал runtime.log: 2 MiB + три ротации, редактирование известных токенов, bearer и ключей, сокращение сторонних HTTP-логов. Это не ограничивает все журналы launchd или сторонних процессов; файловая система должна оставаться защищённой, резервные копии содержат приватный контекст.
- `founder_jarvis/runtime.py`: ежедневная проверка backup в фоне, фильтрация локальной очереди по владельцу, диагностика общей очереди, версия 07. Существующий flock сохраняется. Автономность не расширена; уведомления не увеличены. При нештатном выходе нет гарантии немедленной остановки уже начатых внешних вычислений.
- `founder_jarvis/shared_business.py` + `Backend/HotelsWorker/src/kelvin.js`: протокол 7, owner-scoped diagnostics (только агрегаты статусов и timestamp); повтор finish с тем же ID, lease, status и answer идемпотентен, если исходный ответ уже закоммичен. Один повтор при временной ошибке, без повторов при HTTP 4xx. Старая/изменённая аренда не может записать новый ответ. Если подтверждение потеряно дважды, пользователь может открыть сохранённый результат в истории; гарантии exactly-once доставки Telegram не даются. Lease завершённой записи остаётся в приватной D1 для проверки replay, не возвращается в историю. Старый backend несовместим с новой диагностикой.
- `founder_jarvis/memory_migrate.py`: preflight проверяет protocol 7 перед запуском сервиса при существующем pairing.
- `founder_jarvis/macos/install.sh`: проверка локальных БД и backup перед запуском; croniter установлен как обязательная зависимость обоих Python окружений; тест импорта ядра и тесты эксплуатации. Версия 07. Изменение реального Mac/установка зависимостей здесь не выполнялись.
- `founder_jarvis/macos/control.sh`: журнал runtime, отсутствие Ollama не считается ошибкой статуса Claude.
- `founder_jarvis/macos/doctor.py`: локальная диагностика без раскрытия конфигурации, опциональный --live для Telegram getMe и диагностики backend (не getUpdates и не отправка сообщений). Не подтверждает модель без реального запроса.
- `founder_jarvis/test_operations.py`: 10 новых тестов включая backup/restore, повреждение, WAL, ротацию, редактирование секретов, owner isolation, retry, ускоренный 72h, диагностику.
- `Backend/IumrahBackend/tests/kelvin.test.mjs`: 2 новых теста для протокола 7.
- `founder_jarvis/macos/integration_fixture.py` и `Backend/IumrahBackend/tests/kelvin-http-fixture.mjs`: локальный HTTP-тест двух реальных транспортных реализаций. Фиктивный владелец и SQLite in-memory, сервер привязан только к 127.0.0.1; не запускать как production endpoint.
- Оригинальные upstream src/openjarvis файлы, распаковщики и workflows не изменялись. Переиспользуются SystemBuilder, JarvisSystem, Orchestrator, TaskScheduler, SchedulerStore, EventBus, WebSearchTool.

## Фактическая проверка
- Kelvin: `PYTHONPATH=src:. python -m unittest discover -s founder_jarvis -p 'test_*.py'` — 156 пройдено, 0 failed. ResourceWarning о незакрытых SQLite соединениях в некоторых тестах остаются (не доказательство production-утечки).
- Business backend: `node --test tests/*.test.mjs` из Backend/IumrahBackend — 263 пройдено, 0 failed. Node 22 SQLite тестовый адаптер, не D1 production.
- Upstream scheduler/store: 41 passed, 2 failed, причина отсутствующий croniter в Linux проверочной среде. Установщик теперь явно включает зависимость, фактический повтор с установленной зависимостью на Mac требуется. Upstream не переписан.
- Симуляция 72 часов: 4320 минутных шагов, повторное открытие базы каждые 137 шагов (32 открытия), 3 уникальных утренних уведомления, 6 исследовательских заданий, 12 завершённых заданий. Не wall-clock soak, не реальная модель/сеть.
- Loopback: `PYTHONPATH=src:. python -m founder_jarvis.macos.integration_fixture /path/to/Business` — PASS; pairing, typed memory, shared queue, finish retry, voice metadata and exact lookup, insight publication, token revocation. Не реальные Telegram/Claude/D1.
- `bash -n` изменённых shell-скриптов, Swift syntax parse предыдущего интерфейса и исполняемые pure Swift тесты voice policy — PASS. Полная сборка Xcode и новый интерфейс не проверены. Не акустические испытания.

## Незакрытые критерии блоков 02–07
1. Memory: FTS5/BM25, не полноценная семантика; произвольное извлечение фактов и синхронизация всех задач ещё ограничены. Local compatibility mode не эквивалент общей D1 памяти. Customer memory отдельно в Care.
2. Research: штатный Orchestrator и планировщик, но оригинальные Deep Research, Operative, Monitor Operative и браузер не активированы напрямую; анализ ограничен curated search topics и поисковыми выдержками. Нет полноценной независимой проверки страниц. Качество стратегических выводов модели ещё не измерено.
3. Business: реальные деньги, отказ/атрибуция и прибыль не определяются без соответствующих данных. Не выполнять бизнес-операции через LLM.
4. Care: шаблонный FAQ с контекстными уточнениями, не свободная генерация; real delivery и ручной перехват требуют staging. Оставить production automation выключенной до подтверждения. Instagram/Facebook не включать.
5. Voice: последовательная речь → запрос → ответ, не streaming LLM и не full duplex. Прерывание нажатием микрофона, не голосом без рук. Русский/узбекский: 0/40 реальных акустических испытаний, наличие UZ on-device voice не подтверждено, ElevenLabs не подключён. Реальные состояния и новый UI требуют интеграции с актуальным репозиторием.
6. Production: фактические 72 часа, CPU/RSS/p95 на Intel 8 GB, Xcode archive, D1 backup/restore, dependency install, реальные Telegram и Claude и проверка security под нагрузкой не выполнены. VPS и платные подписки не добавлены. Мак должен быть доступен для inference. Сроки/качество не гарантируются.

## Порядок приёмки после получения актуального Business-репозитория
1. Сверить актуальные GitHub snapshots с исходными архивами и всеми изменёнными файлами. Не заменять новый UI старыми Sources/Views или project.yml. Выполнить трёхстороннее объединение backend; подключить новые экраны к реальным endpoints history, message, turn, records, insights, pair/revoke, и состояниям queued/running/done/failed, отмена воспроизведения отдельно от серверной задачи. Применить прежний HotelDetailView hotfix только если ещё нужен. Проверить наличие usage descriptions/entitlements и target membership.
2. Выполнить полный backend CI и Xcode build, проверить staging. Перед production — резервная копия D1 и точный commit rollback. Не загружать текущий backend candidate до merge с новым репозиторием.
3. После backend v7: установить накопительный Kelvin ZIP, дождаться распаковки; на Mac `cd ~/Kelvin && git pull --ff-only && bash founder_jarvis/macos/install.sh`. Существующие секреты сохранены. При отсутствии pairing выполнить `bash founder_jarvis/macos/link-iumrah.sh` с ключом из Business. Не публиковать токены.
4. `"$HOME/Library/Application Support/Kelvin/telegram-venv/bin/python" -m founder_jarvis.macos.doctor --live` из корня Kelvin. Затем /health, реальный короткий запрос модели, /autonomy status, тест записи/исправления/удаления памяти через разные каналы; /biz status без включения автоматизации. Проверить реальные 40 речевых фраз по инструкции Block 06, не считать пропущенные фразы успешными.
5. Провести реальные 72 часа работы: ровно один утренний брифинг в день при доступном Mac, нет очереди дубликатов после сна/сети/перезапуска, измерить RSS/CPU и задержку запросов, сверить стратегии с реальными бизнес-данными. Отдельно проверить тестового клиента Care до активации production. Проблемы устранять по фактическим логам. При необходимости остановить `bash founder_jarvis/macos/control.sh stop`.
