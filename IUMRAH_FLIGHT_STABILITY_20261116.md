# iumrah Business — Flight stability (2026-11-16)

## Установка — существующий workflow не менять
1. Загрузить `iumrah-business-update.zip` в корень актуального Business-репозитория. Дождаться `Apply iumrah Business ZIP update` и проверить коммит.
2. Запустить существующий Actions → Deploy iumrah backend → Run workflow без изменений конфигурации.
3. После успешного deploy запустить привычный TestFlight билд. В авиабилетах → «Опубликованные» открыть «Резервная копия рейсов» → «Скачать JSON». Сохранить в «Файлы».
4. Плановый запуск ботов продолжает работать по существующему расписанию 08:00 / 20:00 Asia/Tashkent. Не требуется менять GitHub workflow, создавать Worker или D1.
5. Скрипт восстановления из `iumrah-core` оставлен в накопительном патче, но не запускается автоматически. Экспорт из этой базы работает без переноса данных. Дополнительный ручной запуск мониторинга и AeroDataBox из workflow не включён.

## Независимый экспорт JSON
- Авторизованный read-only GET `/api/admin/package/flights/curated/export`: все записи `published=1` из основной базы (включая истекшие, помеченные `expired`), чтение порциями по 200 без лимита 500. Черновики исключены.
- Если основная база не содержит опубликованных записей или чтение не завершилось, пробуется `iumrah-core`, затем непустой предыдущий Flight Sync snapshot текущего сотрудника в доступной базе. Источники не смешиваются, резервные явно маркированы `export_source`, дата снимка и `requires_price_recheck` сохранены. Snapshot может быть неполным/устаревшим; это не подтверждение цены.
- Файл содержит ID, маршрут, даты, сегменты, номера рейсов, цены за человека, валюту, тип тарифа и другие доступные поля; полный объект itinerary сохраняется для строк D1. Снимок экспортируется в исходном сохранённом формате. Нет доступа к бронированиям, паролям или токенам.
- В приложении непустой корректный экспорт автоматически кэшируется по аккаунту в защищённом локальном файле при обновлении каталога, даже если ChatGPT Sync не сработал. Ранее сохранённая основная копия не перезаписывается резервной, ошибкой или пустым ответом. Кнопка «Скачать сохранённую копию» доступна без нового запроса внутри авторизованной сессии; ранее выгруженный файл в «Файлах» доступен отдельно от приложения. Если ни одного снимка нет, данные не выдумываются и пустой файл не выдаётся.

## Изменения
- Миграционный сценарий `CloudflareMigration` направлял `curated_flight_offers` в `iumrah-core`, а рабочее API читает `iumrah-hotels`. API теперь отличает пустой каталог от найденных активных записей в старой базе. Отдельная ручная процедура переносит только ранее опубликованные активные записи из проверенных bindings, не удаляя исходные данные и не перезаписывая независимый каталог. Сохраняются исходные цены и даты наблюдения; они не становятся новыми подтверждёнными тарифами.
- Flight Sync не стирает старый снимок при нуле и не принимает подозрительное сокращение без совпадения с актуальным серверным каталогом. Настоящее сокращение каталога после истечения дат или ручных удалений допускается при подтверждённом непустом наборе ID, маршрутов и цен.
- Боты фиксируют каждую завершённую задачу в D1, а терминальный отчёт агрегирует результаты данного run ID. Отдельные календарные ошибки/отсутствие точного совпадения не останавливают весь обход. Системные ошибки и официальные HTTP-блокировки остаются явными.
- Календарь поддерживает дополнительные формы полных дат, ограниченный переход между месяцами и безопасный отказ от отключённых дат. Проверка на реальных изменённых сайтах ещё требуется по артефактам Actions.
- При HTTP 403 Flynas не обходится антибот-защита. При наличии Ignav ключа часть существующего дневного бюджета теперь выделена на маршрут/дату активных рейсов без свежей цены. Это отдельный источник, а не официальный тариф Flynas.
- Aviasales использует имеющийся `TRAVELPAYOUTS_API_TOKEN` либо `AVIASALES_DATA_TOKEN`. Если обоих нет, источник останется не подключённым. AeroDataBox проверяет расписание, а не цену; запуск опционален.
- iOS не удаляет истёкшие записи на чтении, не очищает текущий мониторинг при временной сетевой ошибке, не синхронизирует черновики, показывает краткий статус и раскрываемые технические детали. Сохранение данных на экране работает в пределах уже загруженного состояния; отдельный постоянный кэш JSON-экспорта добавлен, без изменения политики авторизации.
