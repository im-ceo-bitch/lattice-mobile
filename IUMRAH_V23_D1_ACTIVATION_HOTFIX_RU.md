# V23 — D1 Activation Hotfix

Ошибка из production-лога: `CLEAN_LAUNCH_API_FAILED:d1/database:HTTP_400`. Worker развернулся; точный запрос был скрыт общей диагностикой V22.

- GET выполняются без Content-Type; проверка каталога D1 использует тот же запрос, что успешный preflight.
- Вместо глобального PRAGMA foreign_key_check проверяются все прикладные таблицы по отдельности; внутренние sqlite_ и _cf_ исключены.
- Подсчёт записей выполняется отдельными SELECT COUNT(*) с пакетированием до 10; при HTTP 400/422 пакет повторяется отдельными read-only запросами без пропуска проверок.
- Диагностика сообщает привязку, стадию, таблицу, HTTP и числовой код Cloudflare, не раскрывая значения секретов, персональные данные и сырые ответы.
- Неполные ответы, ненулевые клиентские записи, нарушение FK, отсутствие приватного R2 продолжают блокировать активацию.
- Workflow, R2, пользовательские секреты и iOS не меняются.

Локальная проверка npm run check: 77 unified + 39 flights + 90 package + 20 migration = 226/226; TypeScript успешно. Тесты используют локальные SQLite и имитацию Cloudflare API. Production не проверен, причина исходного HTTP 400 не доказана без полного ответа API.
