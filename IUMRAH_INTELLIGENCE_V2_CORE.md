# iumrah Intelligence 2.0 — Core / Business

Deploy this ZIP to lattice-mobile first using the existing `iumrah-business-*.zip` installer. No workflow changes. The additive 0046 migration is mirrored in the existing runtime schema repair (safe on pre-0046 databases); no event deletion or rewriting on deployment. Existing retention still applies. Build a new iumrah Business version after deploying the Worker.

- Existing visitorId UUIDv4 is reused as the installation identity scoped by platform. Legacy events remain readable. A new native installation may have a different UUID, and multiple browser profiles are separate. These counts are not people or store downloads. Old native session IDs are not rewritten.
- Admin > Analytics > Audience: choose period, select a device by pseudonymous UUID and activity, confirm classification. This is a reversible superadmin action; the public endpoint ignores `internal`. Do not classify based solely on model or city. Marking applies retroactively to retained events and new events for the same platform/UUID; previously generated reports are unchanged. Unclassified means not marked as test, not proven customer. Internal markers persist until changed (even after event retention).
- New optional mobile contract fields `deviceModel` (1–48 ASCII letters, digits, spaces, dot, comma, dash, underscore), `osVersion` (safe code <=24). Send the SAME existing visitorId on every session. Do not send serial, IMEI, IDFA, names or GPS. Native instrumentation and secure founder pairing require iOS/Android client repos and a future release. Older events without metadata are unknown; country/city are the latest network observation from Cloudflare request.cf, not the historical geography for the selected period, and may be missing or inaccurate.
- Audience groups 50 installations per page; device session history up to 100; existing session detail up to 250 events. Country/city/model totals are aggregates, not just the visible page. No verified ordered funnel yet. Booking metric is a reported event, not reconciled sales. Daily trends use occurred_at UTC. External aggregates and fresh AI queries exclude marked internal IDs, historical chat/report text does not automatically update.
- Gemini provider model and billing unchanged; error code is passed correctly to Business and AI errors no longer obscure the overview. Real provider availability and request shape remain to diagnose with deployed logs. No live API key used.

Local checks: 21 intelligence tests and 8 router tests on Node 22, Swift frontend syntax parse. Full Xcode build/device QA and Cloudflare production deploy were not performed here. Run the existing CI before release.
