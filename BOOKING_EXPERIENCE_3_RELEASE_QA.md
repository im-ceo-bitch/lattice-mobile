## New QA changes
- Guest recovery by booking number plus a newly verified OTP proof for a previously verified canonical SMS/email contact. No account creation. A proof is consumed once before booking lookup, wrong contact and missing booking return the same error. A new hashed device-specific booking credential is stored in BOOKINGS_DB; existing primary credential remains valid; changed current verified contact or primary credential invalidates secondary grants. Authorized canonical booking API, package and care/Telegram authentication accept secondary grants. On-device recovery clears old in-memory protected booking data and offline documents when replacing a local token. Requires prior contact verification; no manual bypass. Existing provider SMS/email configuration required.
- Guest chat on unclaimed active bookings uses that booking's token. Claimed bookings still require authenticated account chat to avoid disclosure of other trips in the shared account conversation; existing public support phone fallback retained. This does not implement a separate guest conversation for claimed bookings.
- Historical payments: explicit privileged superadmin reconciliation, external reference and reason, actual additional amount, no outstanding unreviewed receipt, no over-credit, one durable reconciliation, audit, preserve legacy receipts. For active/completed historical confirmed trips require full due amount; canceled trips can reconcile actual partial payment and update cancellation snapshot. Refunds and financial close blocked until reconciliation. No actual bank transfer and no automatic assumption of historical payment. Prior ambiguous historical records must be reviewed individually.
- Certificates: explicit correction (new certificate ID, old ID retired) and revocation with reason, immutable history for staff; active customer list and notification reflect the latest data. Previously exported PDFs cannot be remotely erased. Certificate is a memorial document, not a religious or government credential.
- APNs outbox for booking status updates via HotelsWorker, availability delay, payment review, document publication/update, schedule and certificate events. Per-device persistent delivery rows, 5-attempt limit, 24-hour eligibility, exponential backoff via existing five-minute cron, lease, current authorized recipient recheck, skip stale status, stable APNs ID/collapse ID, no private document title in lock-screen notification. No repeated sends for acknowledged rows. Transport ambiguity can still cause duplicates; APNs acceptance is not proof of display. Outbox written after business mutation, not in the same transaction; crash gap remains. No queue when no configured APNs credentials or no device at event creation. Initial booking push and other legacy event types do not all use this queue. SMS uncertain deliveries remain non-retried (avoid duplicate charges/messages); existing email retry extended to completed/cancelled, localized four languages. No provider live calls during QA.
