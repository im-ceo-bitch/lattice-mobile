# iumrah Business — единый каталог авиабилетов и три бота

Версия: 2026-11-09 / накопительный PATCH (поверх `lattice-mobile-main`). Без изменений старых пользовательских / гостиничных баз, бронирований и Apple-подписи.

## Входит в архив

1. Flight Hub Cloudflare Worker: единая D1 `iumrah-flights`, таблицы `flights`, `flight_offers`, `price_history`, `monitor_runs`, `unmatched_observations`, новая `fare_review_queue`.
2. Точное сопоставление цен только по авиакомпании + номеру рейса + маршруту + дате; бот **не создаёт** рейсы; разные тарифы/валюты хранятся отдельно.
3. Защита от неверных цен: резкие скачки выше 2× или ниже половины последней цены отправляются в `fare_review_queue`; прежняя цена сохраняется. Повторная проверка перед продажей обязательна.
4. Отбрасывание прошедших дат, очистка устаревших рейсов Flight Hub по cron. Исторические оплаченные брони из Core D1 не затрагиваются.
5. Браузерные адаптеры Centrum Air (C6), Uzbekistan Airways (HY), Flynas (XY) с защитой от капчи (останавливаются, не обходят), диагностикой и подтверждением номера рейса.
6. Раздел `Авиабилеты → Мониторинг` в Business: поиск, выбор авиакомпании, актуальные цены/история, багаж и доступные места **только если данные найдены**, статусы источников и пагинация каталога.
7. Публичный адрес Flight Hub (`https://iumrah-flight-hub.<subdomain>.workers.dev`) можно вставить в поле «Подключение авиационной D1» прямо в Business, без новой сборки.
8. Скрипт `scripts/seed-from-old-d1.mjs` переносит ТОЛЬКО **действующие идентификаторы рейсов** из старой `curated_flight_offers` в новую D1. Старые цены, пассажиры, отели и персональные данные не копируются.

## Как установить

1. Загрузить `iumrah-business-flight-catalog-bots-cumulative-20261109.zip` в корень `main`. Существующий `.github/workflows/apply-zip.yml` автоматически распакует файлы.
2. **Разовая операция для включения расписания:** заменить СУЩЕСТВУЮЩИЙ `.github/workflows/provision-flight-hub.yml` содержимым `Backend/FlightHubWorker/github-workflow-template/provision-flight-hub.yml` из распакованного архива. Это **тот же workflow**, а не новый. Текущий `apply-zip.yml` намеренно пропускает `.github/workflows/`, поэтому одним ZIP сделать эту замену невозможно. Не обходить эту защиту.
3. В GitHub Actions открыть `Provision new Cloudflare Flight Hub (manual)` → `Run workflow` → `action=deploy`. Используются существующие `NEW_CLOUDFLARE_ACCOUNT_ID` и `NEW_CLOUDFLARE_API_TOKEN`; вручную новые BOT/ADMIN Secrets **не нужны**, они выводятся из двух защищённых деплойных Secrets на CI. Дополнительные ключи Ignav/AeroDataBox **необязательны**, пока соответствующий источник ещё не интегрирован.
4. После deploy взять из лога `Flight Hub URL ...workers.dev`. В Business открыть **Авиабилеты → Мониторинг → Подключение авиационной D1** и вставить этот **публичный URL, без токена**; нажать «Проверить подключение».
5. Если каталог пуст: вручную запустить `action=seed` в том же workflow. Это работает при доступных **старых** Secrets `OLD_CLOUDFLARE_ACCOUNT_ID` и `OLD_CLOUDFLARE_API_TOKEN`, или при сохранённых `CLOUDFLARE_ACCOUNT_ID` / `CLOUDFLARE_API_TOKEN`, которые всё ещё относятся к старому аккаунту. Если старые credentials перезаписаны, восстановить *только старый read-only* доступ до seed. Этот шаг не извлекает отели и не копирует старые цены.
6. Запустить `action=monitor` для проверки всех трёх сайтов. По расписанию запускаются два раза в день (08:00 и 20:00 Ташкент), до 20 старых рейсов на авиакомпанию за запуск. Ошибки сохраняются как артефакты Actions с экраном сайта.
7. Проверить TestFlight: фильтры, каталог, изменения цены, отсутствие дубликатов и надписи о непроверенных тарифах.

## Ограничения, которые важно знать

- Внешние сайты НЕ дают гарантию доступности, цены и багажа до оформления. Боты читают только видимую цену в публичном бронировании. При изменении DOM, появлении CAPTCHA или ограничении доступа монитор честно сообщает об ошибке и **не публикует** непроверенную стоимость. Ни один из трёх сайтов **не был проверен до успешного live price capture** в этой среде — их адаптеры ещё требуют первого реального запуска и, вероятно, калибровки селекторов. Нельзя считать их уже рабочими на production.
- Flight Hub не содержит полной миграции Core D1, авторизации и бронирований. Этот патч не переключает старую операционную базу и не трогает API отелей.
- Для реального обновления цены сначала должны существовать идентификаторы рейсов в **новой** `iumrah-flights` (seed/import Ignav). Боты НЕ находят автоматически все рейсы по всему миру и не создают новые рейсы.
- Скрипт seed не копирует старые цены из `curated_flight_offers`: после переноса цены появляются только из новых наблюдений.
- GitHub `schedule` может запускаться с задержкой; браузерные адаптеры не обходят антибот-защиту. Соблюдайте условия сайтов и лимиты запросов.
