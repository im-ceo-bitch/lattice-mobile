# iumrah Business — Public Trip Shares · 20.11.2026

Обновление предназначено **только для `lattice-mobile-main` (iumrah Business)**. Это дополнение к уже загруженным пользователем патчам веба, iOS и Android от 20.11.2026. Не загружайте в Web/iOS/Android.

## Что внедрено в действующий единый Backend

- `Backend/IumrahBackend/package-engine/src/index.ts`: обработка `POST/DELETE /api/package/booking/{bookingId}/share`, `GET /api/package/shares/{viewerToken}` непосредственно в реальном PackageEngine, без отсутствующего `business-v10.tar.gz` и без отдельного Worker.
- `Backend/IumrahBackend/src/router.js`: узкое исключение только для двух маршрутов просмотра/управления общими ссылками; остальные заблокированные Core-маршруты остаются под прежним защитным cutover-гейтом.
- `Backend/IumrahBackend/package-engine/src/booking-share.ts`: токен зрителя генерируется криптографически, в D1 хранится только его SHA-256; создать/отозвать ссылку может только владелец по проверенному токену бронирования либо действующей сессии аккаунта, привязанной к брони.
- Ответ зрителю имеет строгий whitelist: даты, маршрут, номер рейса и авиакомпания, отели, услуги, агрегированные статусы виз/билетов. Не возвращаются ФИО, паспорт, виза PDF, PNR, номер электронного билета, личные QR, оплата, токен брони, идентификаторы паломников. Ни один публичный токен не предоставляет права на изменение, оплату или выдачу документов.
- Для общих ссылок читаются **актуальные** статусы `pilgrim_trips`, только подтверждённые `trip_flights` и публикации документов `booking_travel_documents` + `booking_document_publication_v3`. «Готово» выводится только если заполнены соответствующие опубликованные документ-слоты для всех зарегистрированных паломников. Если данных недостаточно — «не подтверждено».
- `Backend/IumrahBackend/migrations/0002_booking_public_shares.sql`: безопасные `CREATE IF NOT EXISTS`; миграция запускается через уже существующий `npm run deploy` перед публикацией Worker. Старые записи не удаляются, существующие таблицы не изменяются.
- `Backend/IumrahBackend/scripts/check-deployed.mjs`: после публикации дополнительно проверяется наличие обработчика публичных ссылок и таблицы D1, чтобы 404 от обычного маршрутизатора не считался успешным результатом.

## Порядок установки

1. Положить **ZIP целиком** в корень GitHub-репозитория `lattice-mobile-main` на ветке `main` и закоммитить. Не распаковывать вручную: установленный workflow **Apply iumrah Business ZIP update** подхватит имя `iumrah-business-*.zip`, распакует файлы, удалит архив и закоммитит изменения.
2. После успешного применения патча открыть GitHub **Actions → Deploy iumrah backend → Run workflow**. В отличие от ZIP-установщика, эта публикация запускается **вручную** по `workflow_dispatch`.
3. Перед публикацией workflow проверяет пакет, D1/R2, собирает единый Worker и применяет аддитивную миграцию. После деплоя он запускает проверку публичного API.
4. Для проверки реальной функциональности (без распространения приватных данных): войти как владелец, открыть подтверждённую бронь, нажать «Поделиться», открыть `/s/{viewerToken}` в браузере без сессии, проверить, что доступны только разрешённые сведения, затем отозвать ссылку и проверить, что она выдаёт 404. **Не публиковать токен владельца и реальные приватные документы в логах или задачах поддержки.**

## Совместимость

Патч не меняет расчёты цен, банковские операции, роуты других бизнес-сервисов, KYC, SMS, push или Telegram. Он использует существующий `iumrah-backend` и его D1 `BOOKINGS_DB` + `HOTELS_DB`. Веб и мобильные клиенты должны быть уже обновлены тремя ранее полученными ZIP; здесь они намеренно не дублируются.

Если Core ещё не активирован, сам маршрут не восстанавливает старые/отсутствующие брони в `iumrah-core`: требуется фактическая доступность записей в той же `BOOKINGS_DB`. Нельзя подменять это созданием пустой базы или отключением защитных проверок. Разрешение доступа по ссылке — всегда «только просмотр».
