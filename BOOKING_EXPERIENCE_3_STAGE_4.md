## Stage 4
- Selected-booking travel companion for ready-to-travel and in-trip states: days/dates in Saudi timezone, next action and today schedule from booking-specific itinerary; explicit execution states, stale schedule notice, schedule/guide/document/package/eSIM/Advisor/ziyarat/support navigation; existing offline document center. Existing package deep links preserved, status and itinerary push open appropriate booking sections. Guest support falls back to existing public iumrah support phone; unified account chat remains account-scoped. Advisor uses existing ritual flow (not a new paid entitlement or voice backend). Schedule refresh on active view, manual pull refresh and push; eSIM selection is booking-specific, in-memory eSIM cache cleared across credential transitions and access failures. No false claim that an event has happened by clock.
- Completed and cancelled trips accessible in main booking archive, including documents, package and schedule; completion animation respects reduced-motion setting. Feedback is private to the booking and staff, 1–5 stars, optional <=1500 chars, only completed trips, one durable review, repeated submission returns original. New staff push is best-effort. No public publication.
- Per-pilgrim memorial certificate: explicit manager confirmation of actual ritual after completed status, complete named traveler, duplicate-safe, private records scoped to booking. Client generates shareable PDF with name, dates and certificate ID, no passport data, protected temporary file cleaned on share dismissal. Not an official religious or governmental certificate. Certificate update push localized for four languages. Not a public verification service; correction/revocation is not implemented in this patch.
- Business itinerary editor has optional local start/end times with strict HH:mm validation, same-day interval (split overnight events into two days); old clients omitting times preserve them, changes reset old execution state. Writes serialized with booking mutation lease. Schedule-change push after commit; no automatic dispatch retries yet. Staff-entered event titles are not automatically translated. Existing package-generated fallback retained.
- Financial closing separate from customer trip completion: recorded verified payments, recorded external refunds, actual manually entered expense total, retained funds with explanation and explicit reconciliation confirmation; immutable closeout with calculated result and audit, duplicate close/refund rejected, pricing override blocked after close. Historical/unverified payments and overpayments on completed trips block financial closing; manual reconciliation workflow still pending. No transfer or accounting-system integration. Retention must follow contract/law; the software does not decide refund entitlements.
- New additive repeatable tables in existing 0044 migration, no destructive migrations. Backend authorization reuses staff routes and requireClientBooking (verified account or booking token); no cost/retention info in customer checkout.
