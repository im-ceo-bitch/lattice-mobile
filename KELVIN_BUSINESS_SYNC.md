# Kelvin Business Sync — iumrah Business + Mac + Telegram

## Установка
1. Загрузить `iumrah-business-kelvin-sync-20261127.zip` в корень lattice-mobile. Дождаться Apply iumrah Business ZIP update. Распаковщик и YAML не меняются.
2. Actions → Deploy iumrah backend → Run workflow. Используется существующий единый Worker, новые таблицы создаются идемпотентно при первом запросе. Никаких DROP/изменений таблиц бронирования. Деплой требует действующей конфигурации unified Core.
3. Actions → iumrah Root — iOS TestFlight (new Team) → Run workflow; включить upload_to_testflight при необходимости. Проверить сборку и установить новую версию. Kelvin: Обзор → Kelvin или Аккаунт → Управление → Kelvin. Требуется авторизованный superadmin с активным защищённым сеансом устройства.
4. Второй архив `jarvis-update-kelvin-iumrah-sync.zip` загрузить только в репозиторий Kelvin (kepler-maneger-), дождаться распаковки.
5. В iumrah Business открой Kelvin → … → Подключить Mac. Подтверди создание ключа (он отзывает предыдущий). Ключ показывается один раз; не публикуй его, не отправляй в чат. Лучше открыть Business на своём Mac (если установлено) для копирования; на iPhone ключ можно прочесть и ввести непосредственно на Mac.
6. На Mac: `cd ~/Kelvin && git pull --ff-only && bash founder_jarvis/macos/link-iumrah.sh`. Введи ключ в скрытый запрос. Скрипт использует существующее Python-окружение и перезапускает зарегистрированный LaunchAgent; при отсутствии сервиса запускает установщик. Не требует повторного ввода Telegram-токена, если старая конфигурация сохранилась.
7. В приложении проверь статус MacBook на связи, отправь вопрос. Затем в личном Telegram-боте спроси об ответе из приложения. Проверь обратное направление и заметку «Запомни: ...». Проверь голосовой ввод и воспроизведение ответа на устройстве. /health в Telegram показывает наличие настройки связи; фактическую доступность подтверждает ответ.

## Архитектура и ограничения
- Существующий `HOTELS_DB`: `kelvin_links` (SHA-256 хеш ключа), `kelvin_turns` (единая история, очередь и lease), `kelvin_memory` (общие заметки). Серверный доступ только через действующий защищённый сеанс superadmin либо отдельный отзываемый ключ Mac. Ключ не даёт доступ к обычным admin API.
- Исходящие HTTPS-запросы от Mac к `https://iumrah-backend.helloiumrah.workers.dev/api/internal/kelvin`. Нет публичного порта, VPS или отдельного Worker. В приложении видны последние 60 запросов, в контекст модели передаются последние 20 завершённых общих обменов и до 30 общих заметок плюс до 20 существующих локальных заметок. Старые локальные диалоги V1–V5 не мигрируются; остаются на Mac. Явные старые команды Telegram (/ig, /biz, /schedule и др.) сохраняют старую реализацию и не синхронизируются в общей истории. Общие обычные сообщения идут в единую очередь; это режим аналитики и консультаций без произвольных операций записи. При потере связи Telegram не создаёт отдельный локальный диалог.
- Агрегаты: статусы бронирований, последние 7 дней, будущие поездки, support threads и сообщения, Telegram Care темы и очередь, заявки Care, подписки Telegram, каталоги отелей/рейсов, события приложения; по явно указанному IUM-ID — сводка одной поездки без документов/контактов. Не считать каталоги актуальным наличием, суммы бронирований прибылью; legacy и business chat counts могут пересекаться. Отсутствие таблицы обозначено available:false.
- Claude Code на Mac отвечает на общие запросы. При запросе о рынке/конкурентах и утреннем отчёте используется оригинальный OpenJarvis WebSearchTool в отдельном окружении, если оно установлено и поиск доступен. Поисковый запрос фиксированный и публичный; данные клиентов в него не передаются. Это не переключение всех native agents OpenJarvis и не полноценный произвольный поиск. Claude работает удалённо в рамках подписки и её условий; не отправлять секреты, паспортные и платёжные данные. История Kelvin хранится в Cloudflare D1. Для строго локального интеллекта потребуется иной настроенный движок.
- Первый утренний отчёт после 08:00 по Asia/Tashkent, затем один отчёт в день при доступности Mac (после сна/простоя — в тот же день). Идентификатор отчёта постоянный для даты. Оригинальный Telegram Care webhook не изменён; автоматические ответы клиентам не переключены. Instagram API, автоматические отправки клиентам и выполнение операций записи в CRM не входят в этот патч.
- Native SwiftUI Canvas: файл KelvinVoiceOrb.swift из утверждённого прототипа. Микрофон использует on-device SFSpeechRecognizer (ru-RU), уровень микрофона анимирует сферу; в голосовом режиме можно перенести распознанный текст в поле ввода. Ответ можно прослушать AVSpeechSynthesizer. Состояние озвучки анимируется, но не по фактической амплитуде выходного звука. При недоступном on-device распознавании используется текст/системная диктовка. Не WebRTC и не прямой звонок. Android не входит в предоставленный репозиторий.
- Работа 24/7 условна: Mac на питании, открытая крышка, сеть, вошедший пользователь. При отключении Mac сервер сохраняет запросы до возобновления. Lease 15 минут, максимум 3 попытки при прерывании; завершённые ответы сохраняются до отправки Telegram. Если доставка Telegram не удалась, ответ доступен в приложении; автоматической повторной отправки нет. Отзыв ключа в приложении отключает Mac, история сохраняется.
- Проверка: node:test на SQLite-адаптере D1, 224 backend-теста; Python 41 тест (37 существующих + 4 bridge); Swift синтаксис разобран Linux swiftc, не Xcode typecheck/build. Реальный Cloudflare D1, TestFlight, Mac, голос, Claude и Telegram end-to-end не проверены. Изменения не затрагивают workflow, подписи, bundle ID и конфигураторы.
