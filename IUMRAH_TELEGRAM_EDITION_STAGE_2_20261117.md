# iumrah Telegram Edition — накопительное обновление 2/2

База: `iumrah-business-telegram-edition-01-cumulative.zip`, ранее собранный на `lattice-mobile-main 8.zip`. Включены все изменения первого этапа (Telegram Care, Gemini-классификация, Business Inbox, фирменный Mini App). Первый ZIP устанавливать отдельно не требуется. GitHub Actions не изменены. Отдельный старый бот и Worker не удалены.

## Второй блок
- Поиск внутри Mini App: опубликованные прямые рейсы туда/обратно, каталог отелей Мекки и Медины, существующие готовые пакеты. Smart Configurator: город, месяц, продолжительность, состав группы, выбор рейсов, отелей и категорий номеров, автомобиля и питания. Готовый пакет предлагает соответствующий отель первым; перед заявкой выполняется новый расчёт.
- Единственный источник цен — Package Engine: опубликованные flight IDs повторно проверяются сервером, проверяются город и вместимость номера, состав группы, маршрут, количество ночей и автомобиль. Непрозрачный AES-GCM черновик связан с Telegram ID и ограничен по времени (14 минут); supplier proof не выдаётся клиенту отдельно. Использован текущий server quote/commit API. Повтор одного запроса идемпотентен; изменение контакта/OTP после начала попытки требует нового расчёта.
- Guest checkout: имя, фамилия, телефон, email; подтверждение одного контакта по существующему OTP API. Регистрация/пароль не нужны. Telegram-уведомления — явное согласие. При согласии действующий Telegram подписывается на статусы и получает зашифрованный booking grant; без согласия бронь создаётся без подписки. Номер и подтверждение — из канонического API. При задержке materialization показывается системный ID. Восстановление поездки по номеру и коду на ранее подтверждённый контакт; прежняя одноразовая привязка сохранена.
- Поездки: активные и завершённые, переключение броней, обновление, статусы, расписание, просмотр/скачивание опубликованных документов, заполнение данных паломников, загрузка фото паспорта, реквизиты и QR оплаты, загрузка фото чека и просмотр его статуса. Разрешённые статусы и право на действие проверяет канонический HotelsWorker. Не публикуется произвольный URL приватного ресурса; только собственная привязанная бронь и существующие опубликованные файлы.
- 4 локализации: RU, EN, UZ Latin, UZ Cyrillic. Технические ошибки API показываются с кодом; данные поставщиков и названия могут быть на языке источника. Добавлены тесты на signed identity, чужой доступ, неизменность цены, вместимость, повтор запроса и отсутствие обязательной Telegram-подписки.

## Установка
1. Применить только `iumrah-business-telegram-edition-02-cumulative.zip` через существующий apply-zip процесс в `lattice-mobile-main`.
2. После успешного применения вручную запустить `Deploy iumrah backend`.
3. Собрать новый Business TestFlight для раздела Чаты → Telegram Care. Убедиться в успешной настройке webhook/menu на новом Worker.
4. Проверить реальную гостевую покупку в Telegram, OTP email/SMS, расчёт, появление брони в Business, переход статуса, открытие PDF и фото, отправку чека, ответ оператора. До этих проверок не удалять прежний бот/Worker и не открывать публичные продажи.

## Границы
- Каталог работает с уже опубликованными рейсами/категориями номеров и существующим кэшем пакетов, не добавляет покупку отдельных авиабилетов, новых поставщиков, Nuitee live room offers или новый источник расписаний. Отсутствие опубликованных данных не заменяется выдуманными предложениями. Расчёт может быть оценочным; подтверждение наличия обязательно. Нет прямого списания картой: используются действующие реквизиты/QR и проверка чека сотрудником. Выбран один автомобиль и существующая серверная модель питания, поезд Haramain не добавлен в новый мастер.
- Gemini Care остаётся ограниченным утверждённой базой ответов/сценариями первого этапа: не реализован автономный агент для формирования пакета по произвольному тексту в чате. Пакет формируется через Mini App.
- Скачивание PDF зависит от Telegram WebView. Фотографии при отправке преобразуются в JPEG существующим клиентским конвертером. Не проведены реальный Telegram/Gemini/OTP/поставщик/платёж или production-деплой, полный iOS build. Нет новых секретов; требуются действующие настройки и опубликованная база. 34 ранее обнаруженных падения отдельного HotelsWorker из первого этапа не исправлялись; его код не изменён во втором блоке.
